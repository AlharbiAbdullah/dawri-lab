# Tasks

One file per lesson. Every task has the same shape, top to bottom:

```
The concept
  The problem                     what is wrong today, with evidence
  What we want                    the outcome, in a few lines
  What you will understand        the ideas, one line each
  Before and after                the change at a glance
  Guardrails                      what must stay true in every tier
Easy / Mid / Hard
  Target output                   what done looks like, exact
  Spec                            numbered steps, exact names, columns and counts
  Withheld                        the mechanisms you work out yourself
Reference                         payload shapes, raw columns, facts. Look up, do not read through.
```

Read the concept before touching code. If the problem is not clear,
ask before starting the easy tier.

## Standing rules

These hold for every task and are not repeated in the files:

- No skeleton on purpose. The design decisions are the lesson.
- Specs state scope exactly. Only mechanisms are withheld.
- Steps that start with "In chat" are answered in words, in the
  conversation, not in a file.
- A tier is done when its target output matches. Then say so and the
  code gets reviewed.
- Tiers build on each other: easy first, hard is optional.
